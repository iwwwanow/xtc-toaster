# Пиксели как частицы и переход между изображениями

Долгий ящик. Идея нового вида тоста — анимированного: на входе два изображения, на выходе последовательность кадров (через `assembleVideo`). Это не операция `Layer` / `Composition` (они делают из одной картинки одну), а отдельная операция над двумя картинками.

**Частицы.** Каждый пиксель — частица `{x, y, vx, vy, цвет, home}`. На кадр: силы (гравитация, пружина к дому, curl noise, отталкивание, затухание) → интегрирование (Эйлер / Верле) → splat в `Uint8ClampedArray`. Дыры при разлёте закрывать точкой 2×2 или блюром. На CPU — сотни тысяч частиц за кадр, для запекания видео хватит; живой просмотр 1080p (2 млн) — только GPU (WebGL / WebGPU compute).

**Переход A → B, например красное в красное.** Нейросеть не нужна — нужна она только для семантического морфинга (глаз в глаз). Аналог Blend в Illustrator: сопоставить точки и интерполировать.
1. Маска по hue ± tolerance (уже есть `mask` с falloff) → два облака точек `PA`, `PB`.
2. Выровнять количество: прореживание / дублирование до общего N или split/merge частиц.
3. Сопоставление — optimal transport. Венгерский алгоритм O(n³) не годится; брать **sliced OT**: случайное направление, проекция, сортировка обеих групп, пары по рангу, сдвиг вдоль направления, 20–50 итераций, O(n log n). Ещё проще — сортировка по кривой Гильберта или углу вокруг центра масс. Яркость / hue в ключе сортировки — чтобы тёмно-красный летел в тёмно-красный.
4. Анимация: `lerp(a, b, ease(t))`, цвет — lerp в LCH. Или физика: цель — точка в B, пружина + затухающий шум → «рой».
5. Фон (не-маска): crossfade, чёрный или исходный A.

Другие способы перехода для справки: crossfade (без движения), классический морфинг Beier–Neely (ручные пары линий), optical flow (для похожих кадров).

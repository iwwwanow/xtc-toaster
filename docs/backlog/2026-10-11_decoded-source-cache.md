# Кэш декодированного исходника по imageId

Сейчас одна и та же картинка декодируется много раз. При загрузке `upload.ts` → `decodeImage` (`packages/server/src/codec.ts`) декодирует её только ради проверки формата и размеров для лимита 2 MP, а пиксели выбрасывает. Затем на **каждом** рендере `run-graph.ts` → `loadInput` → `imageFileToRawData` (`packages/lib/infrastructure/index.ts`) заново читает файл с диска и декодирует его через `canvas` (`loadImage` → `drawImage` → `getImageData`), даже если менялся только параметр ноды.

Нужно держать в памяти сервера декодированные пиксели по `imageId`: первый рендер декодирует, следующие берут из кэша. Можно класть в кэш сразу при загрузке, раз `upload.ts` всё равно декодирует. Это кэш, а не состояние: его можно потерять в любой момент (LRU по памяти, TTL), сервер остаётся stateless. `imageId` — uuid неизменяемого файла, поэтому инвалидация не нужна. Кэш отдаёт только копию: `createLayerFromPixelData` не копирует, `Layer` хранит переданный массив как есть, а часть операций lib может менять его на месте. К тому же в worker пиксели уходят transferable-буфером, и отправленный оригинал в основном потоке становится пустым.

Это половина идеи из `docs/backlog/2026-10-08_server-render-cache.md`, без её сложной части. Кэш результатов нод меняет поведение noize с `Math.random`, а кэш исходника детерминизм не трогает и делается отдельно. С рендером в worker (`docs/backlog/2026-10-11_render-pipeline-evolution.md`) декодирование остаётся в основном потоке и коротко его блокирует — кэш убирает и эту блокировку, кроме первого рендера. При нескольких инстансах кэш у каждого свой, это нормально.

Сейчас не делаем.

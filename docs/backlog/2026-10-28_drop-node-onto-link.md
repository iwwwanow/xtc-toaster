# Нода, брошенная на связь, встаёт в неё

Тащишь ноду на связь A → B и отпускаешь — связь рвётся и получается A → нода → B. Так работает blender (auto-attach: связь под нодой подсвечивается во время переноса, Alt при отпускании отключает вставку). Там же есть auto-offset: ноды справа раздвигаются, чтобы освободить место. Его можно брать вторым шагом.

У xyflow такого нет, пишем сами:
- во время переноса (`onnodedrag`) ищем связь под нодой — через `document.elementsFromPoint` в центре ноды по `.svelte-flow__edge` или через сэмплы безье — и подсвечиваем её;
- на `onnodedragstop` вставляем ноду.

Правила вставки:
- в связь встаёт только **несвязанная** нода, у которой есть и вход, и выход (не input и не output);
- composer встаёт верхней строкой — или не встаёт вообще, решить;
- новый граф проходит `validateGraph`, как и любая нарисованная связь (`canConnect`).

Чистая функция `insertOnLink(graph, nodeId, edgeId) → edges | null` ложится рядом с `withoutTaken` / `canConnect` в `packages/web/src/graph.ts` и тестируется без браузера.

## Архитектура клиента — обсудить до реализации

Вопрос: применять ли clean / application layer с use-cases на клиенте. Use-cases уже есть, просто не выделены в слой: `canConnect`, замена занятого handle, операции над строками composer (`composer.ts`), импорт и экспорт toast, теперь ещё вставка в связь. Сейчас это чистые функции в `graph.ts` / `composer.ts`, а `session.svelte.ts` одновременно хранит состояние, вызывает их и ходит в socket / upload.

Слои, если их выделять:
- domain — `contract` (`ToastGraph`, `validateGraph`);
- application — use-cases как чистые `(состояние редактора, ввод) → новое состояние` над моделью без типов xyflow;
- infrastructure — адаптеры: xyflow (`FlowNode` ↔ граф, позиции, выделение), ws, upload, файлы;
- ui — компоненты, которые вызывают use-cases через session.

Порты, DI и репозитории для SPA на ~1200 строк — лишнее, как и в lib, где взяли DDD-lite без репозиториев (`docs/backlog/2026-08-28_ddd-lite-go-ffi-architecture.md`). Разбивка ложится на рефакторинг спринта 7 вместе с `docs/backlog/2026-10-27_run-graph-mixed-responsibilities.md`.

## Спецификация из blender (решено 28.10)

Use-cases клиента не придумывать по одному, а пройтись по node editor blender и выписать всю спецификацию: выделение (рамка, клик, Shift, Ctrl, всё / инверсия), перенос, дублирование, удаление (с переподключением — Ctrl+X), вставка на связь и auto-offset, mute, frames, группы, переподключение связей, горячие клавиши. Получится список use-cases для application-слоя и QA-лист. Перед тем как выписывать — **согласовать с пользователем**, что брать и в каком объёме. Код blender — C под GPL, берём только поведение.

# Аудио → готовые time-window для ноды animation

Идея пользователя от 10.11, пока сырая. Сначала её записали как «ноду с выходом true / false, которая прерывает time-window с заданной частотой». В тот же день пользователь уточнил, откуда берётся ритм: из аудиофайла.

## Суть

К графу подключается аудиофайл, но не напрямую, а через промежуточную ноду-анализатор. Анализатор разбирает звук и предлагает набор готовых time-window для ноды animation, нарезанных по звуку. Внутри окна цепочка работает, вне окна выключена. Вместе получается true / false во времени: картинка мигает, переключается или режется в ритм трека. Частота окон — это не параметр, который выставляют руками, она берётся из аудио.

## Из чего может состоять

- **Нода audio.** Загружает файл так же, как input загружает картинку (upload на сервер, `audioId`). Длина трека задаёт длину анимации или хотя бы подсказывает её.
- **Нода-анализатор.** Её вход — аудио, выход — набор окон, то есть отрезков `[from, to]` в кадрах. На выбор несколько режимов: доли или такты (beat detection), атаки (onsets), громкость выше порога, может быть, полосы частот (бас / середина / верх). Пользователь берёт готовую нарезку, ему не нужно ставить окна руками.
- **time-window в animation.** Окна приходят проводом от анализатора. Их можно подправить руками, как ключи.
- **Экспорт.** mp4 собирается с исходным звуком, через тот же ffmpeg (`assembleVideo` уже умеет видео). Gif остаётся без звука.

## Что решить

- Где анализировать звук. Есть два варианта: на сервере (ffmpeg плюс анализ, например aubio или essentia) или в браузере через Web Audio API. Во втором случае окна приходят на сервер уже числами.
- Как привязать звук к кадрам. Окна считаются в кадрах при текущем `fps`. Если `fps` поменять, их нужно пересчитать из секунд.
- Сначала нужны сами time-window (`docs/backlog/2026-11-03_timeline-time-windows.md`).
- В графе появится первый не числовой провод (аудио, набор окон). Новые типы нод и необязательные поля формат тоста не ломают (CLAUDE.md, «toast format»), поэтому решать до 1.0 не обязательно.

Близкая идея — клип из картинок по словам аудио (`docs/backlog/2026-10-17_audio-to-image-clip.md`). Там тоже нарезка звука на отрезки, но по словам, а не по ритму.

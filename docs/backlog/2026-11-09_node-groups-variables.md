# Переменные, константы и группы нод — переиспользуемый пайплайн как нода

Идея пользователя 09.11: внутри одной ноды собрать короткий пайплайн и использовать его дальше как обычную ноду, со своими входом, выходом и выведенными наружу параметрами (node group в blender). Сюда же константы и переменные: одно значение, проведённое проводом в параметры нескольких нод, как Value-нода в blender. Провода параметров уже есть (`sourceHandle` у дорожек анимации), так что константа — это нода с одним числовым выходом, а не новый механизм. Это отличается от «composer как группа» (`docs/backlog/2026-10-26_composer-as-node-group.md`): там группа — только рамка в ui, а здесь она входит в контракт. Нужен формат определения группы в тосте и её разворачивание в DAG на сервере перед `runGraph`, а значит, `TOAST_GRAPH_VERSION`. После 1.0 это будет `+1` с миграцией, поэтому формат группы лучше решить до заморозки или сделать его необязательным полем. На этом же можно построить duplicate (`docs/backlog/2026-11-09_delay-and-duplicate-nodes-trail.md`): N экземпляров одной группы.

## 10.11: в релиз, первая версия

Пользователь хочет группы в релиз 28.11. Он называет их самой жирной фичей. Название — **group** (как node group в blender), константа — **value**. Горячих клавиш нет, пользователь откладывает их как можно дольше.

**Как пользоваться (набросок):**
1. Выделить ноды (рамка с Shift).
2. Над выделением появляется панель с кнопкой `group`. Та же команда есть в меню правой кнопки по выделению. Правая кнопка по одной невыделенной ноде по-прежнему сразу удаляет её: сестре это понравилось. Ноды сворачиваются в одну ноду `group 1`.
3. Провода, которые пересекали границу, становятся входом, выходом и параметрами группы. Пиксельный провод становится её входом или выходом. Провод `param → track` наружу становится параметром на ноде группы, и его можно анимировать.
4. Войти в группу — двойной клик или кнопка `open` на ноде. Внутри видны ноды group input и group output, сверху путь `toast › group 1`. Клик по `toast` в этом пути возвращает наружу.
5. Группа появляется в меню слева, в разделе `groups`. Её можно тащить оттуда ещё раз. Все экземпляры связаны: правка внутри меняет их все.
6. `ungroup` (на панели или в меню) разворачивает группу обратно в ноды.

**value** — нода с одним числовым полем. К ней подключают параметры нескольких нод, и все они получают её значение. Если анимировать value одной дорожкой, синхронно двигается всё, что к ней подключено. Так закрывается идея «одна дорожка на несколько параметров». Внутри группы value удобно выводить наружу как один параметр.

**Первая версия:**
- ровно один пиксельный вход и один выход, иначе `group` отказывает с объяснением;
- без вложенных групп;
- без «отвязать экземпляр».

В тосте добавляется необязательное поле `groups` (определения) и тип ноды `group` (экземпляр со ссылкой на определение). Сервер разворачивает группы в обычный DAG до `validateGraph` и `runGraph`. Поле необязательное, поэтому `TOAST_GRAPH_VERSION` остаётся 1. Если не успеваем, группы переезжают в 1.1 без миграции. Оценка — 4–6 дней.

## 11.11: value — решения, factor отдельной нодой

- **Направление провода — `param → value`**, как `param → track` и `param → delay → track`: провод идёт от параметра к тому, что его задаёт. Value принимает провода параметров, у неё один вход на много проводов. Собственное поле value — обычный числовой параметр: его можно вести в дорожку (или через delay), и тогда анимация идёт во все подключённые параметры. Value → value — цепочка, петля отказывает.
- **Число сырое**, как Value в blender: каждый параметр получает его как есть и обрезает по своим границам. Поле −1000…1000, тянуть грубо, точное значение — вводом.
- **Доля 0–1 — отдельная нода `factor`** (рабочее имя), не режим value: число в value всегда значит одно и то же. Подключается так же, `param → factor`, параметр получает `min + v·(max − min)` своего диапазона. Порядок (решено 11.11): value → factor → группы.

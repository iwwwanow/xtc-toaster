# Разделить web, server и contract — отдельные версии, обратная совместимость

Решено 19.10, в спринте 3: пока один образ — Bun отдаёт собранный `dist`, `/api/*` и `/ws` (`docs/sprints/sprint-3.spec.md`). web и server выезжают одной версией, поэтому общий `contract` не может разъехаться между ними. Это осознанное упрощение на время до релиза.

Дальше — три отдельно версионируемых части:

- **contract** — отдельный пакет со своей версией (semver). Ломающее изменение схемы — major. Сообщения ws и файл тоста несут версию (`TOAST_GRAPH_VERSION` уже есть у графа), сервер принимает и текущую, и предыдущую.
- **server** — чистый API (`/api/*`, `/ws`), свой образ и релизы. Обязан понимать клиентов на предыдущей версии contract, пока они живы (вкладка, открытая до деплоя).
- **web** — после сборки это только статика. Своего бэкенда ей не нужно: отдать файлы умеет любой статический сервер (caddy / nginx образ, позже CDN), Bun для этого избыточен. Тогда же возвращается решение «reverse proxy отдаёт статику» — `docs/backlog/2026-10-06_deploy-reverse-proxy-single-origin.md`.

Почему не сейчас: разделение имеет смысл только вместе с правилами совместимости (версии в сообщениях, поддержка N−1, тесты на старых клиентах), а до релиза 28.11 контракт ещё меняется каждый спринт. Вернуться после 1.0 или когда web и server понадобится выкатывать независимо.

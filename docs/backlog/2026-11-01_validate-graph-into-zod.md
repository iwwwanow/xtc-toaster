# Правила графа — внутрь zod-схемы (идея, рефакторинг спринта 7)

`validateGraph` (`packages/contract/src/validate.ts`) можно повесить на `ToastGraphSchema` через `.superRefine()`. Тогда `parseToastGraph` будет сразу отдавать полностью валидный граф, а ручные проверки в web `fromToastFile` (ровно один input / output, повторяющиеся id) уйдут как дубль. Сами правила (циклы, одна связь на вход, связь со строкой только у `layers`) zod декларативно не выражает, так что обход графа останется тем же кодом, только вызываться будет из схемы. Выигрыш — около 20 строк дублирования и одна точка входа.

Два условия, без которых переносить нельзя. Первое: `validateGraph` остаётся отдельной функцией, потому что web `canConnect` вызывает её на каждом входе, над которым проносят связь, специально без zod-парса (это скорость). Второе: `nodeId` должен дойти до ошибки. Его нужно положить в issue (`params: { nodeId }` или `path` на ноду) и достать на сервере, иначе граф с ошибкой станет безымянным «bad message» вместо `render-error` с подсветкой ноды. Решено 01.11: не сейчас, в рефакторинге спринта 7 (contract).

# Canvas портит цвет полупрозрачных пикселей — исправить

Canvas (и node-canvas/cairo на сервере, и браузерный) хранит пиксели с предумноженной альфой — `r·a`, `g·a`, `b·a` в 8 битах. При каждом проходе через canvas цвет полупрозрачного пикселя квантуется с шагом примерно `255 / a`, и чем прозрачнее пиксель, тем сильнее он портится. Это нужно исправить, а не просто зафиксировать.

Проверено 2026-10-08 на пикселе `(200, 100, 50)` с разной альфой. Для сравнения PNG собирался и читался вручную через zlib, без canvas:

| альфа | декод через canvas (`imageFileToRawData`) | энкод через canvas (`rawDataToImageFile`) |
|---|---|---|
| 255 | 200, 100, 50 | 200, 100, 50 |
| 128 | 199, 99, 49 | 199, 100, 50 |
| 30 | 204, 102, 51 | 196, 94, 43 |
| 5 | 204, 102, 51 | 153, 51, 0 |
| 1 | 255, 0, 0 | 0, 0, 0 |

Потеря есть на обоих концах, так что чтение плюс запись её складывают. Тест `packages/lib/tests/infrastructure.test.ts` («semi-transparent colors survive within premultiplication error») сейчас просто разрешает расхождение до 8 при альфе 30.

Почему это важно: маски lib (`hue` / `saturation` / `value` с falloff) пишут вес совпадения в альфу. Полупрозрачные пиксели — это все мягкие края масок, и их цвет искажается при каждом экспорте. В истории экспортов (`docs/backlog/2026-10-08_raw-rgba-frames-export-history.md`) ошибка будет накапливаться: экспорт → импорт → снова экспорт. Для jpeg-исходников и текущего signac (вся альфа 255) проблема не проявляется — поэтому и не в спринте 1.

Где canvas участвует сейчас и будет участвовать:

- `lib/infrastructure`: `imageFileToRawData` (декод), `rawDataToImageFile` (энкод);
- `server/src/codec.ts`: `encodePng`;
- браузер: `putImageData` для показа и `canvas.toBlob` для скачивания, если так сделать.

Направление фикса: байты, которые сохраняются или скачиваются, никогда не проходят через canvas. PNG кодировать и декодировать прямо из сырого RGBA без предумножения. Формат простой (фильтр по строкам + deflate, zlib есть и в Bun, и в браузере через `CompressionStream`), либо взять готовый pure-JS / wasm-кодек. На клиенте — тот же кодек в worker вместо `canvas.toBlob`. Через canvas остаётся только показ на экране, там потеря не важна. При переходе на Skia (`docs/backlog/2026-10-06_native-backend-zig-skia-migration.md`) кодеки и энкодеры умеют работать без предумножения (`kUnpremul_SkAlphaType`) — проверить это явно. Связано с переносом кодека в lib: `docs/backlog/2026-10-06_image-codec-into-lib.md`. Признак готовности: тест в `infrastructure.test.ts` требует точного совпадения при любой альфе, включая 1.

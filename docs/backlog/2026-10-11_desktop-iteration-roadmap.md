# Путь к десктопу: итерации фронт → native бэк → native UI

Двигаюсь итерациями, а не одним большим переездом:

1. **Фронт.** Довожу текущий Svelte + `@xyflow/svelte` до рабочего UI/UX. Если десктоп понадобится раньше, промежуточный вариант — Tauri (или Electrobun) с тем же фронтом и Bun-сервером как sidecar. Фронт при этом не переписывается.
2. **Бэк → native.** Перенос lib на Zig + Skia за границей рендера: `docs/backlog/2026-10-06_native-backend-zig-skia-migration.md`, `docs/backlog/2026-10-06_render-boundary.md`.
3. **Фронт → профилирование → native.** Сначала замеры. Переход на нативный UI-инструмент — только если узкое место окажется в webview. Браузерная версия при этом сохраняется через WebAssembly (ImGui и Skia/CanvasKit умеют собираться в wasm).

Ограничения на выбор инструмента для п. 3:

- логику нод (pan/zoom, связи, выделение, перетаскивание) руками не пишу — инструмент должен давать это из коробки, по уровню как svelte-flow;
- UI/UX не отлаживаю на низкоуровневых инструментах: UX обкатывается на вебе в п. 1, а нативный слой его только повторяет;
- ближе к делу — подобрать кандидатов и провести предварительное тестирование: нода с живым превью, wasm-сборка, ввод кириллицы, диалоги файлов.

Главный аргумент за п. 3 — общий GPU-контекст UI и рендера: `docs/backlog/2026-10-11_native-ui-shared-gpu-context.md`.

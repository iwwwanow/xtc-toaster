# Предупреждения рендера (warnings), а не только ошибки

Сейчас у рендера два исхода: `rendered` или `render-error` с одним `nodeId`. Часть ситуаций — не ошибка, а недособранный граф: в строку composer подключена цепочка, в начало которой ничего не входит (не доходит до input). В спринте 4 это `render-error` на висящей ноде (решено 27.10, проще); правильнее — рендерить без этой строки и предупредить.

Форма: `rendered` получает необязательное `warnings?: [{ message, nodeIds }]` (аддитивно, старые клиенты не ломаются); `runGraph` собирает предупреждения в массив вместо throw, worker и ws пробрасывают их; web подсвечивает ноды жёлтым и пишет текст (сейчас ошибка — только текст в `OutputNode.svelte` про одну ноду). Оценка ~полдня: contract 15 мин, server ~1 ч, web 1–2 ч. В плане — stretch 5 спринта 4.

Тем же механизмом потом можно предупреждать о мусоре в висящих ветках (цикл, двойная связь вне предков output) — сейчас `validateGraph` проверяет весь граф и падает с ошибкой; для warning пришлось бы делить проблемы на «влияет на output / не влияет» (+1–2 ч). Ценность низкая: web с спринта 4 такой граф нарисовать не даёт, остаются только старые и рукописные файлы.

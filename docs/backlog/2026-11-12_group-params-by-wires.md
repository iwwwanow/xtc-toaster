# Параметры группы — проводами в group input, а не списком в group output

Сейчас выведенные параметры задаются только при `group`: провода параметров наружу превращаются в поля. Group output просто перечисляет их текстом (`angle ← rotate.angle`), и пользователю непонятно, откуда эти строки и как добавить ещё один (12.11). Пользователь предложил задавать их проводами — в group output или, логичнее, в group input. Group input ближе к blender (поле экземпляра — это вход группы) и к нашему направлению проводов `param → value`: group input для внутренних параметров работает как value-нода. Тогда group input получает строки как delay: провод `param → свободная строка` выводит параметр, а снятый провод его убирает. В одну строку можно завести несколько параметров, и одно поле экземпляра задаст их все, как value. Group output остаётся только для пикселей. В формате это станут связи определения `inner.param → groupInput:<id>` вместо поля `params` — до 1.0 формат можно ломать. Открыто: какие границы у строки с несколькими параметрами разных диапазонов (сырое число с обрезкой, как у value?) и как называть строку (по первому параметру, с правкой имени).

## 12.11, вечер: решено пользователем

- **Провода в group input.** Строки как у delay: провод `param → строка` выводит параметр, а снятый провод его убирает. Group output остаётся только для пикселей.
- **Внутри группы точка параметра — слева.** Точка параметра на поле стоит справа, а group input — слева от всего. Провода в него шли бы назад через ноду, это некрасиво. Поэтому в виде группы точку параметра у полей рисуем слева (`Slider`, `--param-handle-offset` с другой стороны), в корне она остаётся справа. Открыто: переезжают ли влево все точки параметров внутри группы — тогда провода к value / delay внутри тоже выходят слева — или только у тех, что идут в group input. Проще первое: сторона зависит от вида, а не от провода.

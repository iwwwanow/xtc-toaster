# 2026-11-05 — нода анимации в web

Клиентская часть спринта сделана за один день вместо запланированных 05–08.11: разъёмы параметров, нода, дорожки, ключи, playhead и текущий кадр через обычный рендер. Кнопки `render animation` пока нет, она ждёт сервера.

## Что сделано

- `packages/web/src/animation.ts`: чистые функции для дорожек, ключей и таймлайна. `row-drag.svelte.ts`: перетаскивание строк, общее для `layers` и дорожек.
- `Slider` получил `node` и `param`: у него теперь есть разъём, а если у параметра есть ключи, поле становится только для чтения и показывает значение на playhead. Менять 12 компонентов нод по отдельности не пришлось.
- `AnimationNode.svelte`: настройки, колонка дорожек вне скролла, таймлайн, поля выбранного ключа.
- `graph.ts`: `sourceHandle` больше не теряется, провод параметра не влияет на раскладку, `withoutTaken` снимает прежний провод этого параметра.
- В контракте из `graphAtFrame` выделен `animatedValues`, им пользуются поля. Добавлен `INITIAL_DATA.animation`, через него нода попала в меню.
- `tests/toasts/`: `animation`, `broken-animation-two-nodes`, `broken-animation-pixel-link`.

## Что нашлось по дороге

Ребро без `sourceHandle` xyflow вешает на первый исходящий разъём в DOM. С разъёмами в строках все пиксельные провода ушли бы на первый параметр, поэтому пиксельный разъём теперь стоит в разметке раньше `fieldset`, во всех нодах.

У ноды с одним параметром (`blur`, `opacity`) пиксельный выход по центру почти совпадал с разъёмом строки. Выход перенесён на линию заголовка. Это видимое изменение всех нод, пользователь его ещё не видел, решение записано в спеке и его легко отменить.

Первый запуск показал разъёмы по центру ноды: у `.param` не было `position: relative`. Юнит-тесты такое не ловят, нашлось только на скриншоте.

Рендер сейчас получает кадр без ноды анимации. Так смена `fps` или порядка дорожек не запускает рендер, а playhead на участке с постоянными значениями не перерисовывает картинку.

Остальные решения, которые я принял сам, перечислены в конце `docs/sprints/sprint-5.spec.md`.

## Как проверено

`bun run typecheck` и `bun run test` зелёные: contract 157, web 131, server 110, lib 183, toasts 6. Golden-хеши не менялись.

В headless Chrome с настоящим сервером, ошибок в консоли нет:

- `?toast=animation`: дорожки, пунктирные провода, поля только для чтения; клик по линейке меняет картинку, в том числе при зуме и прокрученном таймлайне;
- `+ key`, правка значения (9999 зажимается до 100), отказ при переносе ключа на занятый кадр;
- переброс параметра на пустую дорожку: появляется первый ключ, старая дорожка оставляет ключи и теряет провод; удаление дорожки возвращает полю редактирование;
- `frames` 100 → 24: playhead встаёт на последний кадр; перезагрузка страницы сохраняет граф;
- чистый граф: нода из меню, вторая не добавляется, связь с `blur.radius` даёт первый ключ, пиксельный провод в дорожку отклоняется;
- регрессия: `fork-3` с перестановкой строк `layers`, `toast-2_signac`.

Перетаскивание из меню и перестановка строк проверены синтетическими событиями, а не настоящим drag & drop мышью. Колесо над таймлайном и скролл на трекпаде не проверялись вообще. Руками в обычном браузере это ещё никто не смотрел.

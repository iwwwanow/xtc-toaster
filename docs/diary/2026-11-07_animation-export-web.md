# 2026-11-07 — экспорт анимации в web, gif без срока хранения, белый фон gif

Шаг 5 спринта: кнопка экспорта. Сервер умел `render-animation` с 06.11, теперь его можно вызвать со страницы. Ветка `feat/animation-server`.

## Что сделано

- `ActionsPanel`: кнопка `render animation` под `download png`. Она выключена, если нет картинки, нет связи, идёт загрузка или экспорт, или если ни одна связанная дорожка с ключами не двигает параметр (`hasAnimatedParams` в `animation.ts`: `animatedValues(graph, 0)` не пуст — значение дорожки держится до первого и после последнего ключа, так что кадра 0 хватает). Во время экспорта на кнопке `frame n / N`. Ошибка экспорта — под кнопкой.
- `session.svelte.ts`: `exportAnimation()` останавливает `play` и шлёт весь граф (с нодой анимации) под своим `exportId`. Id растут общим счётчиком на рендеры и экспорт, поэтому рендер, отправленный до экспорта, приходит под своим id и обрабатывается как обычно. `animation-progress` → `exporting`, `animation-rendered` → `fetch(url)` и `saveBlob` как `<toast>_<YYYYMMDD-HHmmss>.gif`, `render-error` → текст под кнопкой (с типом ноды, если есть `nodeId`). Обрыв связи завершает экспорт с ошибкой.
- Блокировка: `exporting` входит в `locked` и `animationLocked`, линейка playhead тоже выключена. `App.svelte` не шлёт рендеры, пока идёт экспорт: сервер берёт по одному сообщению, и рендер вытеснил бы ждущий экспорт. После экспорта текущий граф отправляется заново — рендер, ждавший на сервере в момент экспорта, был им вытеснен, и без повтора `rendering` осталось бы `true`.
- Сервер: gif хранятся бессрочно (решение пользователя 07.11). `removeExpiredAnimations` → `removeLeftoverFrames`: чистит только папки кадров, не тронутые 15 минут (остатки упавшего процесса). Квота uploads gif по-прежнему не считает.
- lib, `assembleGifFromFrames`: каждый кадр перед палитрой кладётся на белый фон (`GIF_BACKGROUND`, решение пользователя 07.11). Фон — `color` источник размером с первый кадр (размер читается из IHDR png), `overlay=shortest=1:format=rgb` в обоих проходах ffmpeg; `format=rgb` обязателен — по умолчанию overlay работает в yuv420 и размывает цвета.
- Планирование: после всех пунктов спринта 5 — ручной проход по ui пользователем, первым в stretch (`sprint-5.spec.md`).

## Как проверено

- `bun run typecheck` и `bun run test` зелёные во всех пакетах; новые тесты — `hasAnimatedParams`, `removeLeftoverFrames` (gif остаются, свежая папка кадров остаётся).
- Headless Chrome на dev-стеке, `?toast=animation`: кнопка → `frame n / 24` (play и `download png` выключены) → скачан `toast-2_signac_<ts>.gif`, 24 кадра, 12 fps, кнопка вернулась. Gif остался на сервере в `uploads/animations`.

## Альфа в gif

У gif прозрачность однобитная. До правки в `tests/toasts/animation.json` (дорожка `opacity` 1 → 0.2) кадры с непрозрачностью выше ~0.5 выходили полностью непрозрачными, ниже — пустыми (с 16-го кадра gif был белый). Теперь кадры сводятся на белый: затухание идёт в белое, проверено тестом lib (красный с альфой 128 → g = b ≈ 127, альфа 255) и повторным экспортом в headless Chrome на dev-стеке (ffmpeg 7.1 в контейнере) — кадры 0…23 плавно светлеют. Прозрачный фон в gif теперь невозможен; если понадобится — цвет фона в настройки экспорта (`docs/backlog/2026-10-26_preview-node-and-export-settings.md`).

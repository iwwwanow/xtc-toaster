# 2026-11-10 — нода, брошенная на провод, встаёт в него

Третья фича из блока «10.11 added before the release» (`docs/planning.md`). Идея — `docs/backlog/2026-10-28_drop-node-onto-link.md`. Ветка `feat/undo-redo`, поверх undo / redo и delay, в master не слита.

## Как сделано

- **Правила — `insertOnLink(nodes, edges, nodeId, edgeId)` в `graph.ts`.** Связь A → B заменяется на A → нода → B. Встаёт нода без пиксельных проводов: провод параметра к дорожке не мешает, анимированную ноду тоже можно вставить. Не встают input / output, animation и delay, потому что у них нет пиксельного входа или выхода. Провод должен быть пиксельным. `layers` берёт связь в верхнюю строку (вопрос из бэклога «верхней строкой или никак» решён так), без строк не встаёт. Связь в строку layers сохраняет свою строку: A → нода → layers:строка. Новый граф проходит `validateGraph`, как любой нарисованный провод. id новых связей — в формате xyflow (`xy-edge__…`).
- **Какой провод под нодой — `linksUnder(rect, paths)`.** В бэклоге предлагалось взять `elementsFromPoint` в центре ноды. Отказался: interaction-путь у ребра шириной 20 px, и провод пришлось бы ловить в ±10 px от центра. Сделал, как в blender: годится любой провод, чья кривая пересекает прямоугольник ноды, а из них берётся тот, что проходит ближе всего к центру. Кривая читается из `d` нарисованного пути (`M … C …` от `getBezierPath`), по ней берутся 64 сэмпла. Что видно на экране, то и ловится. Из найденных проводов берётся первый, который принимает `insertOnLink`.
- **Editor.** `onnodedrag` работает, только если тащат одну ноду. Он пишет найденный провод в `session.dropLink`, и `LinkEdge` рисует этот провод толще (`stroke-width: 4`). На `onnodedragstop` нода вставляется. Прямоугольник ноды строится по `targetNode.position` из события. У `getInternalNode().internals.positionAbsolute` во время перетаскивания позиция отстаёт на одно движение. Из-за этого в headless сначала подсвечивался соседний провод: нода стояла на `ti → op`, а выбрался `ho → ti`.
- **История: одно перетаскивание — один шаг.** Шаг записывается после 300 мс тишины, поэтому раньше пауза посреди перетаскивания уже давала отдельный шаг позиции, а вставка стала бы вторым. Теперь `session.dragging` ставится на `onnodedragstart` и снимается на `onnodedragstop`, и пока он стоит, эффект в `App.svelte` ничего не записывает (и в `localStorage` не сохраняет). Шаг пишется после того, как ноду отпустили. Это правило касается любого перетаскивания ноды, не только вставки.

## Проверено

- Typecheck всех пакетов. Тесты web — 169 (+10): вставка, строка layers сохраняется, layers в верхнюю строку, связанная нода не встаёт, анимированная встаёт, input / output / animation / delay не встают, в провод параметра не встаёт, layers без строк не встаёт; `linksUnder` — порядок по близости к центру, кривая, а не хорда, непонятный путь пропускается. lib 190, server 128, toasts 8.
- Headless Chrome, `?toast=more-nodes` (свободная `fill`), настоящее перетаскивание через `Input.dispatchMouseEvent`:
  - `fill` тянется на середину `ti → op` и 0.8 с стоит над ним: подсвечен `ti → op`;
  - после отпускания `ti → fi`, `fi → op`, `ti → op` нет, подсветка снята;
  - один Ctrl+Z вернул и связи, и позицию `fill`, несмотря на паузу: это один шаг; Ctrl+Shift+Z — снова вставлена;
  - связанная `tint`, протянутая над чужим проводом, ничего не подсвечивает и связи не меняет.
- Скрипты CDP — в scratchpad сессии (`cdp.ts` — минимальный клиент, `drop-on-link.ts`), в репо не клал. Подвох: нода в углу может оказаться под левым меню, тогда нажатие попадает в меню. Хвататься надо за правый край рамки ноды.

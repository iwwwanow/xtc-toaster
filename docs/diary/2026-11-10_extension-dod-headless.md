# 2026-11-10 — сводный прогон DoD расширения спринта 5

Пользователь посмотрел новый UI (шапку таймлайна, группы, ширины, шахматку, handle, mp4) и сказал, что всё в порядке. После этого весь список «definition of done (extension)» из `docs/sprints/sprint-5.spec.md` прогнан одним заходом в headless Chrome на dev-стеке (`?toast=toast-1_degas`, порт 5174). Каждый шаг проверялся отдельным bun-скриптом поверх CDP. Мышь работала через `Input.dispatchMouseEvent`, поэтому pointer capture и xyflow вели себя как при живом курсоре.

## Результаты

- **Тесты.** `bun run typecheck` и `bun run test` зелёные: contract 167, lib 190, toasts 8, web 147, server 127. Тестами покрыто всё, что требует DoD: выведение групп, правила перетаскивания ключей и сводки, prev / next key, арифметика loop для gif и mp4 (`render-animation.test.ts`), поле `export` в схеме и его round trip (`graph.test.ts`, `persist.test.ts`, `validate.test.ts`).
- **Ширина ноды — 1220px, а не 1236.** По сетке получается 6 × 190 + 5 × 16 = 1220, так что в спеке 09.11 была арифметическая ошибка (span-2 = 396 и таймлайн 808 сходятся с 1220). Спеку и planning поправил, код не менялся.
- **Группы.** Их 6: `corners 1/2/3` по 6 треков и `move 1/2/3` по 2.
- **Сворачивание.** Проводов 55 до, во время и после сворачивания. При сворачивании 24 конца уезжают на линию легенды, отступ у всех handle ровно 0px: полустрочного сдвига из дневника 09.11 больше нет. После разворачивания все концы возвращаются в те же точки.
- **Транспорт.** Ключи в треках стоят на кадрах 0 и 23. `end` → 23, `start` → 0, `key ›` → 23 (второй раз остаётся на 23), `›` упирается в 23, `‹` → 22, `‹ key` → 0.
- **Перетаскивание playhead.** По линейке с 25% на 75% кадры шли так: 6 7 8 10 12 13 15 16 17.
- **Зум.** Два щелчка Ctrl+колеса растянули контент с 796 до 1244px (×1.5625 = 1.25²). Точка под курсором осталась на месте (0.500 → 0.499), страница не зумилась. `fit` вернул 796px.
- **Ключи.** Ключ трека 23 → 18: остальные треки группы не сдвинулись, выбор уехал вместе с ключом (в настройках 18 / −1.0542). Тот же ключ потащили на занятый 0: он встал на 1, последний свободный кадр по пути. Ромб сводки `move 1` с 0 на +3 сдвинул ключи обоих треков. Клик без движения выбирает ключ и открывает его настройки.
- **Провод на `+ track`.** Параметр `bottomLeftX` из purple-corners (это группа `corners 3`) бросили на `+ track`. Трек встал первым в `corners 3`, проводов стало 56, ключ появился на playhead (кадр 17). Повторный сброс того же параметра и сброс `topLeftX` (у него трек уже есть) ничего не меняют. Предупреждений xyflow (#008) нет.
- **mp4.** Настройки degas: `seconds 15`, `whole cycles`. ffprobe: h264, yuv420p, 250×360 (исходные 250×359 дополнены до чётного), 36 fps, 552 кадра = 23 цикла × 24, 15.33 с. Файл декодируется до конца без ошибок, рендер 24 кадров занял около 9 с.
- **gif.** 24 кадра 250×359, в loop-блоке NETSCAPE 22 повтора, то есть 23 проигрывания. Ширина панели экспорта 151px.
- **export → import → reload.** Выставили `mp4`, `reps 3` → export toast. В файле `export: {format: mp4, loop: {reps: 3}}`. Потом clear graph (настройки сбросились в `gif` / default) → import → reload без `?toast`. На каждом шаге одно и то же: `mp4 reps 3`, 27 нод, 55 проводов, 6 групп, ключи совпадают.

## Найдено

- **Каждый скачанный файл называется `toast-2_signac_*`, какой бы тост ни был открыт.** В `session.svelte.ts` стоит `const TOAST = "toast-2_signac"`. Это осталось со времён, когда в web был один фиксированный граф. У degas mp4, gif, png и json тоже получают имя signac, а это нарушает соглашение `<toast>_<timestamp>` из CLAUDE.md. Имени в формате тоста нет. Вопрос пользователю: брать имя из пресета или имени импортированного файла, или завести поле в тосте (тогда до заморозки формата в 1.0).
- **Для degas в dev нужен `RENDER_MAX_LAYERS=8`.** В `.env` значение было пустым, поэтому degas падал с `layers: over 4 layers in one render` (это уже записано 01.11). В локальном `.env` выставлено 8, как на проде, server пересоздан.

## Имя скачиваемых файлов

Пользователь решил: каждый файл из web называется `xtc-toaster_<YYYYMMDD-HHmmss>.<ext>`, какой бы тост ни был открыт. Имя тоста не берём ни из пресета, ни из импортированного файла, ни из нового поля, поэтому формат тоста не меняется. Префикс зашит в `outputFileName` (`files.ts`), константа `TOAST` из `session.svelte.ts` убрана, правило в CLAUDE.md обновлено. Скрипт bake для degas называет видео по-своему, его не трогали.

Заодно про ширину: код всегда считал 1220 (`calc(6 * var(--grid-column) + 5 * var(--GRID-GAP))`), ошибка была только в числе в спеке.

## Подводные камни

- На странице два `input[type=file]`: первый — загрузка картинки в ноде input, второй (`accept` с json) — импорт тоста. Если подсунуть тост первому, получишь `png or jpeg only`, и граф останется пустым.
- Заголовок loop-блока gif: `NETSCAPE2.0`, затем `03 01`, затем два байта счётчика. Счётчик начинается со смещения +13, а не +14.

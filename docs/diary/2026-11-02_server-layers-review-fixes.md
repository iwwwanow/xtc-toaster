# 2026-11-02 — ревью разбивки сервера на слои: чистая установка, мёртвый воркер, порт loadImage

Ревью `refactor/server-layers` (коммит `92d4320`) против `master` показало, что ветка в CI не собирается. Остальные находки частью исправили здесь, частью отложили.

## Что сломало чистую установку

Из `packages/server/package.json` убрали `canvas`, но `tests/server.test.ts` продолжал импортировать его напрямую. Линкер в репо изолированный, поэтому на чистом `bun install --frozen-lockfile` падали и `tsc`, и `bun test`. Локально всё было зелёным только благодаря старому симлинку `packages/server/node_modules/canvas` от 10.10. Подводный камень на будущее: зелёный локальный прогон после правки зависимостей ничего не доказывает, проверять надо через `docker build --target test .`.

Зависимость обратно не вернули. В lib появился `decodePixels(bytes)` (`infrastructure/image-codec.ts`): байты png / jpeg → RGBA. Тест сервера проверяет рендер через него, `bun.lock` не менялся.

## Исправления

- **Мёртвый воркер больше не вешает очередь** (`infrastructure/workers/render-queue.ts`). Раньше после смерти воркера ссылка на него оставалась, следующий `postMessage` уходил в никуда, и рендеры всех соединений ждали вечно, а `/healthz` отвечал ok. Теперь на `error` и `close` воркер забывается, текущий рендер получает ошибку, следующий запускает новый воркер. После `error` воркер ещё и завершается через `terminate()`, а его поздний `close` игнорируется, иначе он отклонил бы уже следующий рендер. Ради тестов модуль стал фабрикой `createRenderQueue(workerUrl)`: `render-queue.test.ts` гоняет подставные воркеры из `tests/fixtures/` (выход, необработанная ошибка, падение при загрузке). `canvas` они не трогают, так что запрет на второй воркер с `canvas` не нарушается. Нативный крэш (NAPI fatal) убивает весь процесс, от него это не спасает, там нужен рестарт контейнера.
- **Гонка в `loadUpload`** (`infrastructure/repository/uploads.ts`). Главный поток удаляет файлы, воркер их читает, поэтому между `exists()` и чтением файл мог исчезнуть, и клиент получал сырую ошибку без `nodeId`. Теперь файл читается сразу через `readFile`, `ENOENT` превращается в `null`, а уже прочитанные байты декодирует `decodePixels`. Сам момент гонки тестом не воспроизводится, покрыты только исходы: файла нет → `null`, битый файл → ошибка.
- **Порт `LoadImage`** (`application/run-graph.ts`). Application больше не импортирует infrastructure: `runGraph` и `render` принимают функцию `loadImage(imageId)`, адаптер `loadUpload` подключает `render-worker.ts`. `run-graph.test.ts` и `degas.test.ts` больше не копируют фикстуру на диск. Хэш degas с golden сошёлся, то есть декодирование из буфера даёт те же пиксели, что и из файла.
- **Свой каталог у `uploads.test.ts`**: `tests/output/uploads-repository`. Его `beforeEach` делал `rm -rf` в каталоге `server.test.ts`.

## Проверки

`docker build --target test .` (то, что запускает CI, на чистой установке) прошёл: typecheck и тесты всех пакетов, у сервера 107 pass.

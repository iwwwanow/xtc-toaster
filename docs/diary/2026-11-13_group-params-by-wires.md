# 2026-11-13 — параметры группы проводами в group input

Продолжение `docs/diary/2026-11-12_node-groups-web.md`. Вчера вечером решили, что выведенные параметры группы задаются проводами в group input. Сегодня обсудили открытые вопросы и сделали. Ветка `feat/groups`.

## Решения пользователя (13.11)

- **Одна строка — один параметр.** Вчера я предлагал заводить в строку несколько параметров, как в `value`. Пользователь не понял, как это вообще может быть, поэтому упростили. Границы поля берутся от самого параметра, и вопрос про разные диапазоны исчезает. Нужно одно поле на несколько параметров — внутри ставится `value`, и в строку выводится его собственный параметр (`value.value` — пусть так).
- **Имя строки — `node.param`**, как у строк delay и дорожек animation. Оно берётся из провода, переименования нет.
- **Точки слева у всех полей внутри группы**, у `value` тоже: вывести можно любой параметр.
- **Delay внутри группы не нужен:** animation туда не попадает, delay не к чему подключить. Раньше меню внутри группы давало delay, а `groupSelection` отказывал, только если delay выходит наружу.

## Как сделано

- **Формат.** Поле `params` определения убрано. У `groupInput` теперь `data.rows`, как у delay. Выведенный параметр — это связь `inner.param → groupInput:<row>`. Значения экземпляра и его выходы параметров адресуются id строки. Функция `exposedParams` в contract собирает их по проводам в порядке строк. `expandGroups` не копирует связи в group input.
- **Проверки.** Связи в group input проверяются отдельно от остального определения (`exposingIssue`): из числового параметра, в существующую строку, одна связь на строку. Выведенный параметр больше никуда внутри не заведён — иначе у него было бы два хозяина. Delay добавлен в `NOT_IN_A_GROUP`.
- **web.** `groupSelection` заводит провода наружу в строки `row-1`, … со свободной внизу, а delay в выделении — отказ. `GroupInputNode` рисует строки как delay (`withFreeRow`, `delayRowName`), точки справа. `GroupOutputNode` — только пиксели. `Slider` ставит точку слева, когда открыта группа. Поле экземпляра и дорожка подписаны `node.param` (`paramName`), канал — по имени группы, `paramLabel` даёт `spin fade.rotate.angle`.
- **Снятый провод.** Если внутри снять провод со строки, у экземпляров остаются своё значение по ней и провод наружу. Contract тогда отказывает весь тост, а xyflow снимает провод сам, без проверки. Поэтому `session` при каждой правке открытой группы вызывает `withoutUnexposed`: значение и провода наружу уходят в той же правке, один undo возвращает всё. Так же в blender: связи уходят вместе с сокетом. Contract остался строгим.

## Раскладка внутри группы (отзыв пользователя)

После arrange group input уезжал вправо вверх, над group output, — «выглядит отвратительно». Причина: elk ставит источник провода в столбец левее цели. Провод `rotate.angle → group input` для него значит «group input после rotate». Исправлено в `arrange.ts`: провод из точки на левой стороне ноды elk получает развёрнутым. Правило общее, по стороне точки, особого случая для group input нет; в корне левых точек-источников нет, там ничего не меняется. Тест в `arrange.test.ts` без правки падает. В headless Chrome после arrange внутри `spin fade` всё стоит в одну линию: group input, rotate, scale, opacity, group output.

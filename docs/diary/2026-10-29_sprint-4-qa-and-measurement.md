# 2026-10-29 — спринт 4: QA composer и замер слоёв

## Замер composer под лимитами прода

Прод-образ (`docker build .`, ветка `feat/composer` на `6f1184f`) запущен локально с лимитами прод-compose: `--read-only`, `--tmpfs /tmp`, `--memory 512m`, `--cpu-shares 256`, `--cap-drop ALL`, загрузки на tmpfs. Картинка — poppies, растянутая до 1180×1694 (1,999 Мп, чуть под `UPLOAD_MAX_MEGAPIXELS`): фикстура всего 250×359. Граф: input → N цепочек по 2 ноды (blur 8 + hue noise, isolate + opacity, tint + blur 4, hue noise + tint, blur 12 + opacity — по кругу) → composer на N строк (normal / add / lch-hue по кругу) → output. На каждое N — свежий контейнер, 1 прогрев + 3 замера, потом `memory.peak` из cgroup (`/sys/fs/cgroup/system.slice/docker-<id>.scope/`, systemd-драйвер). Ноутбук i5-6300U, во время первого прохода нагружен (load ~6) — время только относительное, память переносится на прод.

| строк | время, с (3 прогона, второй проход) | `memory.peak`, МиБ | oom |
|---|---|---|---|
| 1 | 2,1–2,2 | 298–307 | 0 |
| 4 | 4,3–4,6 | 373–379 | 0 |
| 7 | 7,2–7,3 | 414–419 | 0 |
| 10 | 14,5–19 (первый проход) | 474 | 0 |
| 16 | 17–19 | 460 | 0 |
| 32 | 36–37 | 501 | 0 |
| 48 | 56–57 | 512 — упёрся, 84 МиБ в swap | 0 |

- Память растёт медленно: ~13 МиБ на строку сверх базы. База на одной строке ~300 МиБ (на проде в спринте 3 было 212 — тогда в графе не было blur, а box blur держит временный `Float64Array` размером с картинку, ~61 МиБ на 2 Мп). Пик немонотонный (16 строк ниже 10): у лимита GC bun собирает агрессивнее, `memory.peak` отчасти меряет момент сборки, а не рабочий набор.
- Упирается не память, а время: рендер один на процесс (один worker, общая очередь), время растёт линейно, ~1,1–1,3 с на строку на ноутбуке. На проде один vCPU с `cpu_shares: 256` — скорее медленнее.
- На 48 строках рендер выжил только за счёт swap ноутбука: в прод-compose `mem_limit` без `memswap_limit`, есть ли swap на проде — не проверял.
- Лимит считает строки, а не ноды: длинная цепочка blur 20 стоит времени, не занимая слот. Время одного рендера ничем не ограничено.

Решение: прод `RENDER_MAX_LAYERS=8` — покрывает degas (7 слоёв), пик ~430 МиБ, запас ~80 МиБ; больше — только дольше очередь. Вписать в прод-compose (`iwwwanow_infrastructure`, `stacks/ru-timeweb/xtc-toaster/compose.yml`) вместе с выкаткой `0.5.0`. Скрипты замера остались в scratchpad сессии, в репо не попали.

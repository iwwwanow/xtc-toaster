## Формат (решено 11.11, после 1.0 замораживается)

- В тосте необязательное поле `groups`: определения `{ id, name, nodes, edges, params }`. Внутри ровно одна `groupInput` и одна `groupOutput`, нельзя `group` (без вложенности в v1), `animation` (она одна на граф и стоит снаружи), `input` / `output`. `params` — выведенные наружу параметры: числовой параметр внутренней ноды под своим id. Выводить можно и число value / factor внутри.
- Экземпляр — нода `{ type: "group", data: { group, params? } }`. `params` — собственные значения выведенных параметров у этого экземпляра; если значения нет, берётся значение внутренней ноды. Экземпляры одного определения связаны. У экземпляра один пиксельный вход, один выход и по выходу параметра на каждый выведенный параметр (`sourceHandle` = id параметра). Ведётся как любой параметр: в дорожку, delay, value, factor.
- Поле необязательное, поэтому `TOAST_GRAPH_VERSION` остаётся 1.

## Как сделано

- **`expandGroups` (`contract/src/groups.ts`)** превращает граф с группами в обычный. Каждый экземпляр становится копиями нод определения с id `<экземпляр>/<нода>`, собственные значения экземпляра вписаны в их data, внутренние связи скопированы. Концы внешних связей разрешаются двумя функциями:
  - `sourcesOf` — откуда на самом деле выходит связь: из того, что питает `groupOutput`; при `groupInput → groupOutput` напрямую — из того, что питает сам экземпляр. Для выведенного параметра — параметр внутренней ноды;
  - `targetsOf` — куда на самом деле входит: в то, что питает `groupInput`, кроме самого `groupOutput`. Пробрасывание учитывается только со стороны источника, иначе A → B получилось бы дважды.
  Два экземпляра подряд и разветвления работают сами. `instanceOf` по префиксу `<экземпляр>/` находит экземпляр развёрнутой ноды.
- **`validateGraph`** теперь проверяет весь тост. Сначала группы (`groupsIssue`):
  - каждое определение — одна `groupInput` / `groupOutput`, ничего запрещённого, свои связи как граф (`groupInput` / `groupOutput` подставлены как input / output), выведенные параметры — числовые параметры существующих нод;
  - `groupInput` / `groupOutput` снаружи запрещены;
  - экземпляр ссылается на существующее определение, его `params` — только выведенные и в границах.
  Затем развёрнутый граф проверяется прежним телом (`validatePlain`), а ошибка на развёрнутой ноде указывает на экземпляр. Ошибка внутри определения несёт `group` (новое необязательное поле `GraphIssue`). Все прежние вызовы (web `canConnect`, сервер, импорт) понимают группы без правок.
- **Сервер.** `runGraph` разворачивает группы после проверки. Экспорт анимации разворачивает один раз до цикла по кадрам, так что дорожка на параметре группы доходит до внутренней ноды обычным `graphAtFrame`. Статичный кадр web будет присылать уже развёрнутым, а ошибку на `<экземпляр>/<нода>` web переведёт на экземпляр сам (`instanceOf`).

## Остаток — web (основная часть, ~3–4 дня)

Задумано так:
- состояние: корень и определения (ноды xyflow с позициями) плюс текущий вид — корень или группа; `session.nodes` / `edges` для `SvelteFlow` переключаются по виду. Граф для рендера и проверок собирается из всего: `toGraph` с группами → `expandGroups` → `graphAtFrame`;
- `canConnect` и правила броска (`insertOnLink`, `linkOntoNode`, `keepChain`) должны видеть группы и текущий вид: внутри группы проверяется определение и весь тост с ним;
- создание из выделения — чистая функция: входящие пиксельные провода от одного источника, исходящие из одной ноды, пересекающие провода параметров наружу → выведенные параметры; провод параметра внутрь, delay наружу, input / output / animation в выделении — отказ с объяснением;
- нода экземпляра (имя, `open`, поля выведенных параметров с handle), ноды `groupInput` / `groupOutput`, путь `toast › group 1`, вход двойным кликом;
- тулбар над выделением (`group` / `ungroup` / `open`), раздел `groups` в левом меню, ungroup;
- история и сохранение: группы в снимке, вид — нет (если определение исчезло после undo, вид уходит в корень).

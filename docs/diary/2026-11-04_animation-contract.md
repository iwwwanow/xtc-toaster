# 2026-11-04 — контракт ноды анимации, без вертикального скролла

План на день начинался с проверки разъёмов внутри вертикального скролла. По исходникам xyflow 1.7.0 выходило, что положение разъёма запоминается при замере и при внутреннем скролле не обновляется, у ушедшей строки провод указывает за рамку, а наши разъёмы, вынесенные за рамку, внутри `overflow` обрезались бы всегда. Запускать это не стали. Я предложил тестовую страницу с тремя вариантами разъёмов, пользователь отказался: всё это ради скролла, скролл убираем. Нода растёт по высоте вместе с дорожками, как `layers`, разъёмы и стили остаются текущими. Заметка — `docs/backlog/2026-11-04_animation-tracks-vertical-scroll.md`, туда же ушёл stretch про минимальный и максимальный размер всех нод, потому что он строился на том же скролле. Проверка из спеки снята, контракт из-за неё не меняется: `targetHandle` дорожки остаётся.

Цена решения: 24 дорожки degas дают высокую ноду. Смягчить это может группировка дорожек (stretch 2), но её пока нет.

Ширина 602px осталась, горизонтальный скролл таймлайна тоже. Колонка с именами дорожек лежит вне него, так что разъёмы не обрежутся. Это по расчёту, в браузере не проверяли: ноды ещё нет. Пользователь подтвердил ключи в кадрах.

## Что сделано

В `packages/contract`:

- `AnimationNodeSchema`: `fps`, `frames`, `loop`, `tracks`; `sourceHandle` на рёбрах; `paramBounds` — границы числового параметра по типу ноды.
- `validateGraph`: одна нода анимации на граф, ничего из неё не выходит, параметр числовой и есть у типа источника, одна дорожка на параметр и один параметр на дорожку, значения ключей в границах параметра, кадры в `0..frames-1`, ключи дорожки на разных кадрах.
- `animation.ts`: `valueAtFrame` и `graphAtFrame`. Значение зажато между двумя ключами, чтобы погрешность округления не вывела его за границу параметра: тогда схема отказала бы только на этом одном кадре.

На сервере изменений в поведении нет, только тип. Новые тесты подтверждают, что рендер не доходит до ноды анимации, провод параметра сам по себе не тянет источник, а кадр из `graphAtFrame` даёт те же байты, что граф с этим значением. Заодно проверил `blur`: дробный радиус он округляет сам, так что интерполированные значения для него безопасны.

`bun run typecheck` и `bun run test` зелёные: contract 157, server 110, web 109, lib 183, toasts 6. Golden-хеши не менялись.

## Решения, которые я принял сам

Пользователь их отдельно не подтверждал, записаны в конце спеки:

- `fps` — целое 1–100: gif хранит задержки в сотых долях секунды. Для mp4 границу можно будет расширить.
- `loop` — строгая схема: файл с `reps` и `seconds` сразу отклоняется, иначе zod молча выбросил бы одно из полей.
- Дорожка без провода допустима и ни на что не влияет, как несвязанная строка `layers`.
- ws-сообщения перенесены из сегодняшнего шага в серверный. Форма результата зависит от того, как gif дойдёт до клиента (проверка 3), а текущий `ws.ts` любое клиентское сообщение считает обычным рендером: `render-animation` молча отрисовал бы один кадр.

## Что осталось на шаг web

- Контракт уже пускает ноду анимации, а web её ещё не знает. `toGraphEdge` теряет `sourceHandle`, поэтому файл с анимацией импортируется, но рендер падает с «link a param», а компонента ноды нет. Такие файлы пока никто не создаёт.
- Нода ещё не должна появиться в меню: `INITIAL_DATA` добавит её туда автоматически, вместе с компонентом.
- Уменьшение `frames`, когда ключи стоят дальше нового конца: `validateGraph` такой граф отклоняет, значит web должен что-то сделать с этими ключами. Не решено.
- Провод, брошенный на саму ноду: xyflow подключает только к разъёму, а строки новой дорожки до броска ещё нет. Простейший вариант — постоянная пустая строка с разъёмом, как виртуальный сокет в Blender. Не проверял.

## Дорожки и ключи: решения после контракта

После слияния контракта обсудили два открытых вопроса выше, и оба решились проще, чем я предлагал.

Дорожки работают как строки `layers`: `+ track` добавляет пустую строку с разъёмом, строки перетаскиваются, параметр приходит по проводу. Виртуальный сокет и бросок на ноду не нужны. Направление предложил пользователь: новая строка сверху, как у слоёв. На картинку порядок не влияет, а без вертикального скролла строка снизу оказалась бы далеко от кнопки.

Про ключи за концом `frames` я спрашивал, удалять их или запретить уменьшение. Пользователь спросил, почему их нельзя просто оставить. Причины нет: правило я сам записал в спеку 03.11. Теперь `frames` — только диапазон рендера. Ключ за концом остаётся и продолжает тянуть интерполяцию.

Так же решили с проводом: без него строка и ключи остаются. Ключи могут не влезть в границы другого параметра, поэтому значение зажимается при расчёте кадра в `graphAtFrame`, а сами ключи не меняются. Оба правила ушли из `validateGraph`, список правил выше устарел в этой части. Минус: в файле могут лежать значения за границами параметра, на рендер это не влияет.

Web начинаем завтра. Из списка выше остаётся `toGraphEdge` и добавление ноды в меню вместе с компонентом.

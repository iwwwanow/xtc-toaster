# 2026-11-10 — удаление ноды сохраняет цепочку

Шестая фича из блока «10.11 added before the release» (`docs/planning.md`), обратная к «нода, брошенная на провод, встаёт в разрыв». Идея — `docs/backlog/2026-11-10_delete-node-keeps-chain.md`. Ветка `feat/undo-redo`, слита в master 11.11.

## Как сделано

- **Правила — `keepChain(nodes, edges, removed)` в `graph.ts`.** На входе то, что осталось после удаления, плюс удалённые ноды и их связи. Для каждой удалённой пиксельной связи нода → B, где B жива, ищется источник ноды: её единственная пиксельная входящая связь. Если источник тоже удалён, поиск идёт выше по цепочке, поэтому A → n1 → n2 → B с удалёнными n1 и n2 даёт A → B. Если выход расходился в несколько мест, A подключается к каждому, строка layers у B сохраняется. Нода без единственного пиксельного входа (input, неподключённая, layers с несколькими связанными строками) ничего не сшивает. Провода параметров уходят вместе с нодой. Каждая новая связь проходит `canConnect`, отказанная пропускается.
- **Editor.** Хук `ondelete` у xyflow: `deleteElements` вызывает его после того, как убрал ноды и связи, и передаёт удалённые ноды вместе со всеми их связями. Значит, `onbeforedelete` и запоминание графа до удаления не нужны. `session.keepChain` пишет связи в том же такте, поэтому удаление и сшивание — один шаг истории. Путь общий для правого клика и клавиш Delete / Backspace: оба идут через `deleteElements`.

## Проверено

- Typecheck. Тесты web — 184 (+5): A → нода → B; две подряд; разветвление (в ноду и в строку layers); layers с двумя связанными строками — ничего, с одной — сшивается; провод параметра уходит, неподключённый вход — ничего. Остальные пакеты зелёные.
- Headless Chrome, `?toast=more-nodes` (скрипт `delete-chain.ts` в scratchpad сессии): правый клик по matrix — `pe → ho → ti` стало `pe → ti`; tint и opacity выделены (Ctrl+клик), Delete — `ho → out`. Один Ctrl+Z в обоих случаях возвращает и ноды, и связи.

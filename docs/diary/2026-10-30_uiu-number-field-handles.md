## uiu

uiu `v0.3.0` подключён как bun git dependency (`"uiu": "github:iwwwanow/uiu#v0.3.0"`, `bun.lock` закрепил коммит `5846c23`). Спайк прошёл без сюрпризов: пакет ставится и сервисом `install` в dev compose, и в стадии `deps` прод-образа (`docker build --target test .` зелёный). В `App.svelte` порядок такой: `uiu/owo.css` → `uiu/ai-generated.css` → `@xyflow/svelte/dist/base.css` → `./app.css`.

Что сломал reset owo, увидел по скриншоту в headless Chrome:

- **Пропали все провода.** Правило `svg { max-width: 100% }` сжимает svg ребра до нулевой ширины: у xyflow это svg без размера с `overflow: visible` внутри контейнера нулевого размера. Лечится `.svelte-flow svg { max-width: none }`.
- Весь текст стал 10px: `:root { font-size: 62.5% }`, а размер owo задаёт только `p` / `h*`. Добавлен `body { font-size: 1.4rem }`.
- Пропали рамки fieldset, кнопок и `Controls`, съехали handle строк composer (они были привязаны к паддингу fieldset в `em`).

На классы uiu переведено всё, что он покрывает: кнопки, select, number и text input, чекбокс в строке composer, ошибки (`field__error`), баннер соединения (`alert-error`), версия (`field__hint`). Чего в uiu нет, написано в `packages/web/src/app.css`, у каждого блока `TODO(uiu)`: рамка ноды `.frame` (legend как у `.hr_fieldset`, рамка как у `.border`), color input, file input, chrome xyflow, handle. Весь список пробелов с тем, как это перенести в uiu, лежит в `docs/backlog/2026-10-30_uiu-gaps-from-web.md`.

## Поле-слайдер как в blender

Пользователь посмотрел на uiu-шные range (дорожка 1px, синий квадрат 16px, который наезжает на подпись) и попросил number field как в blender. Сделано так:

- в ноде две колонки: подпись выровнена вправо, во второй поле. Рамка ноды теперь grid `max-content 1fr`, строка `.param` — `subgrid`, поэтому колонки совпадают по всей ноде (хорошо видно на perspective). Всё остальное в рамке занимает обе колонки;
- поле размером с `.input-sm`, значение по центру, бледная заливка показывает положение в диапазоне. Перетаскивание по горизонтали: ширина поля соответствует всему диапазону, с Shift в 10 раз медленнее. Шаг квантуется, но точная сумма копится, поэтому мелкие движения с Shift не теряются. На hover появляются стрелки `‹ ›` (±шаг);
- клик без движения открывает ввод значения. Enter или клик мимо применяют, Esc и мусор оставляют старое значение. Введённое значение только зажимается в границы, к шагу не подгоняется: «0.333» остаётся 0.333, а для показа берётся до 4 знаков;
- рендер, как и раньше, один, по отпусканию. Пока идёт рендер, поле заблокировано (`session.locked`, пунктирная рамка).

Логика лежит в `src/slider.ts` с тестами, компонент `nodes/Slider.svelte`. Интерфейс `Slider` не изменился, ноды трогать не пришлось.

Проверял настоящими событиями мыши через CDP (`Input.dispatchMouseEvent`). Нашлось два места:

- второй drag сразу после первого «не работал». Это не баг: после первого отпускания шёл рендер, и поле было заблокировано. В скрипте нужно ждать рендер;
- **настоящий баг**: ввод открывался по `pointerup`, и mouseup того же клика приходил уже в новое поле ввода и снимал выделение. Введённое «-12.5» встало перед «45». Теперь ввод открывается по `click`.

Меню нод: пункты стали кнопками uiu (`btn-sm`), с промежутком и hover.

## Точки соединения (handle)

Пользователь пожаловался, что в точку трудно попасть мышью, а на краю ноды она стоит вплотную к полю. Это тот же пункт сестры «трудно попасть» (stretch 2). Обсудили варианты и сделали четыре из пяти: точку вынесли за рамку, вокруг неё невидимая зона попадания (`::before`, ±9px), на hover меняется цвет, `connectionRadius={40}` (провод, брошенный рядом со входом, прилипает к нему). Пятый вариант, бросок провода на ноду целиком, ушёл в backlog: `docs/backlog/2026-10-30_drop-link-onto-node.md`.

По виду точки было три итерации:

- сначала 8px с увеличением на hover. Пользователю не понравилось: слишком большая, увеличение лишнее, достаточно цвета, «серый другого оттенка» без синего;
- потом сделал круглую 6px. Слово «прямоугольная» я понял как «с углами», а имелась в виду форма. По пикселям его скриншота точка была почти ровным кругом, «овалом» её делал провод, который входит в неё тем же серым. Круглая не нужна;
- итог: квадрат 4px, `--MEDIUM` → `--DARK` на hover, вынесена на 4px от рамки (сначала было 8, слишком далеко).

Урок: если формулировка про форму или размер двусмысленная, сначала нужно уточнить или измерить скриншот пользователя, а не делать по своему прочтению.

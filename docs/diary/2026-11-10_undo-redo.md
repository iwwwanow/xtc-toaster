# 2026-11-10 — undo / redo в редакторе

Пользователь попросил историю операций с Ctrl+Z и обратной операцией и взял её в текущий спринт. Это единственное исключение из правила «без горячих клавиш». Идея — `docs/backlog/2026-11-10_undo-redo-history.md`. Ветка `feat/undo-redo`.

## Как сделано

- **Снимки, а не команды.** Для перезагрузки уже был готовый снимок редактора: `toSaved` / `fromSaved` из `persist.ts` (граф, настройки экспорта, позиции нод). История — стек таких строк (`history.ts`, класс `History`, тесты рядом). Предел — 100 шагов. Операции по отдельности описывать не пришлось, поэтому в историю сразу попадает всё, что меняет граф: параметры, ноды, провода, дорожки и ключи, настройки экспорта, смена картинки, раскладка кнопкой arrange. Выделение, вид холста, playhead и свёрнутость групп в снимок не входят и шагов не дают.
- **Шаг пишется, когда правка улеглась.** Это тот же момент, что и сохранение в `localStorage` (300 мс тишины в `App.svelte`), поэтому перетаскивание или серия правок даёт один шаг. Если нажать Ctrl+Z раньше, ещё не записанная правка сначала записывается, и отменяется именно она, а не предыдущая.
- **Применение шага.** `fromSaved` даёт ноды и провода. У нод, которые уже есть на экране, сохраняется то, что xyflow измерил (`measured`), и выделение. Затем `History.settle` записывает текущим тот снимок, который получился после применения, чтобы его эхо не считалось новой правкой и не стирало redo.
- **Замена графа — один шаг.** Импорт и `clear graph` пишут шаг сразу. Раскладка elk, которая идёт за ними (Editor), дописывается в этот же шаг (`amendHistory`). Без этого получалось два шага, и первый Ctrl+Z показывал ноды кучей в начале координат.
- **Клавиши.** Ctrl+Z, Ctrl+Shift+Z и Ctrl+Y ловятся на `window` по `event.code`, поэтому работают и в русской раскладке. Внутри поля ввода клавиши не перехватываются: там работает отмена самого браузера. Во время экспорта и загрузки картинки история не двигается.
- **Кнопки** `undo` / `redo` стоят вверху панели действий. Стиль группы кнопок написан руками рядом с `.export-group` (uiu не умеет группу кнопок, это уже в `TODO(uiu)`).
- **Только dev.** `?toast=` и `DEBUG_IMAGE` при открытии страницы — не правки пользователя. После них `main.ts` начинает историю заново (`restartHistory`), иначе первый Ctrl+Z после перезагрузки откатывал картинку.

## Проверено

- `bun run typecheck`, тесты web — 153, из них 6 на `History`.
- Headless Chrome, degas:
  - blur 8 → 9: Ctrl+Z вернул 8, Ctrl+Shift+Z — 9, Ctrl+Z с русской раскладкой (key `я`, code `KeyZ`) — снова 8;
  - удаление `red-tint` правой кнопкой (27 → 26 нод, 55 → 53 провода): кнопка `undo` вернула всё, все 55 проводов нарисованы;
  - ключ 23 → 19, Ctrl+Z через 50 мс (правка ещё не улеглась) вернул 23, Ctrl+Y — 19;
  - Ctrl+Z в открытом поле числа граф не трогает;
  - после перезагрузки истории нет;
  - `clear graph` → undo вернул degas уже разложенным, redo — снова пустой граф.

## Подвох

Посреди проверки перетаскивание ключа «перестало работать». Оказалось, vite после правок отдавал `session.svelte.ts` по двум адресам с разными `?t=`: на странице было два экземпляра session, и нода animation смотрела в неподключённый. Лечится `docker compose restart web`, как уже записано в памяти про устаревший vite. Признак — в `performance.getEntriesByType("resource")` два url модуля.

## Остаток

- Ветка `feat/undo-redo` слита в master 11.11.
- Руками пользователь undo / redo ещё не пробовал.
- Каждая следующая фича (delay, вставка в провод, копия через Alt, удаление с сохранением цепочки, зоны действий, группы) должна давать ровно один шаг истории на одно действие. Особенно это касается тех, что меняют ноды и провода в два захода, как импорт с раскладкой (для них есть `amendHistory`).

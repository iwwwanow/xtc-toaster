# 2026-11-19 — вложенные группы, delay в группе, анимация: кривые, cycle, окно таймлайна

Пользователь прислал скриншот: шесть экземпляров `group 1`, у каждого `opacity` и `3d turn angle` через delay идут в value, всё сходится в layers. Выделил всё это, нажал `group` и получил «the delay stays outside a group». Мешали два запрета v1: delay внутри группы и группа внутри группы. Пользователь выбрал снять оба. Дальше в той же ветке `feat/nested-groups` по его просьбам: value в разрыв провода параметра, кривая интерполяции на дорожке, циклический таймлайн для шлейфа и окно таймлайна (start / end). Вечером ветка смержена в master и запушена.

## Анимация

Прежде чем писать код, обсудили, как это работает с анимацией. Нода animation внутрь группы не идёт, она по-прежнему одна, в корне. Таймлайн, fps и экспорт общие для тоста. Экземпляры связаны, так что треки внутри двигали бы их все одинаково. В Blender так же: ключей внутри node group нет. Delay внутри группы только сдвигает время того, что кормит параметр снаружи. На скриншоте это value, которые после группировки становятся строками group input, и трек в корне цепляется к выходу экземпляра. Сдвиг delay общий для всех экземпляров: `frames` не параметр, наружу его не вывести. Можно сделать позже, если понадобится.

Сначала я предлагал не пускать строку delay прямо в group input (`param → delay → groupInput`), потому что это можно сделать через value. Пользователь спросил, чем это обосновано. Довод оказался слабым. Через value поле получает границы value, а не параметра, и имя `value.value`. Треки всегда снаружи, поэтому выделение с `param → delay → трек` без такой связи просто не сгруппировалось бы. Разворачивается такая связь тоже бесплатно: `экземпляр.row → трек` превращается в `delay.row → трек`, а это и так легально. Связь разрешили.

## Contract

- `NOT_IN_A_GROUP` — теперь только animation / input / output.
- `expandGroups` разворачивает по проходу на уровень. Внутренний экземпляр копируется как экземпляр (`<outer>/<inner>`) и разворачивается на следующем проходе — `<outer>/<inner>/<node>`. С `only` (ungroup) делается один проход, внутренние экземпляры остаются экземплярами.
- Собственное значение экземпляра записывается туда, где кончается строка за цепочкой delay (`behindDelays`). Если строка ведёт во внутренний экземпляр — в его `params`.
- `exposedEnd(groups, definition, row)` проходит строку через delay и внутренние экземпляры до обычного параметра. Возвращает ноду, параметр, путь id до неё, границы и значение; собственное значение экземпляра по пути перекрывает значение ноды. На нём держатся проверка границ, поле экземпляра и web.
- Валидация. `nestingOrder` отказывает определению, которое держит само себя на любой глубине («a group can't hold itself»), и проверяет определения изнутри наружу. `definitionIssue` разворачивает внутренние экземпляры перед `validatePlain`. Правила экземпляра (`instancesIssue`) общие для корня и определений. `exposingIssue` принимает всё, что `exposedEnd` доводит до числового параметра; висячая строка delay отказывается.

## Web

- `exposedParams(groups, group)` — через `exposedEnd`. Имя строки такое же, как в group input: `node.param`, через delay `opacity.opacity +4`, через внутренний экземпляр `spin fade.opacity.opacity`. У поля шаг и границы конечного параметра.
- Анимированное значение поля экземпляра `session.animatedValue` берёт по развёрнутому id `[instance, ...path].join("/")`, а не `innerId` одного уровня.
- `groupSelection` / `ungroup` работают на любом уровне (`level`). Внутри группы новая группа вкладывается туда: провод в строку открытой группы становится `новый_экземпляр.row → groupInput:row`. Отказ теперь только на input / output / animation / group input / group output.
- `withoutUnexposed` чистит экземпляры на всех уровнях и повторяет, пока что-то меняется. Строка, отвязанная глубоко внутри, тянет за собой строку внешней группы и провод из неё в корне.
- В сессии путь открытых групп вместо одной (`view: string[]`, `openPath`). Breadcrumbs `toast / wave / group 1`, промежуточные звенья ведут наверх. Undo, убравший группу из пути, обрезает путь над ней.
- Меню: delay внутри группы включён. Группу можно вытащить внутрь другой, кроме самой себя и тех, что её держат (`holds`). `instancesOf` считает экземпляры на всех уровнях: от этого зависят «N instances» и `×`.

## Value в разрыв провода параметра

Пользователь попросил, чтобы value тоже ставился в середину провода параметра, как delay с 18.11. 18.11 я этого не делал: трек тогда анимирует value, а не параметр. Но картинка от этого не меняется — value передаёт своё число параметру. `insertOnLink` → `throughValue`: `A.param → B` становится `A.param → value → B`. B — это трек, строка delay, другой value / factor или строка group input. Ставится только value без связей. Factor не трогал: в разрыве он поменял бы смысл, его число — доля диапазона. `session.insertOnLink` сразу отдаёт value число параметра (`seedValue`), как при ручном проводе. Тесты в `graph.test.ts`. Headless: на `?toast=animation` перетащил `value` из меню на провод `move.y → трек` — провод подсветился, после броска `move.y → value → трек`, трек y теперь в канале `value`, ошибок нет.

## Кривая на дорожке

Пользователь спросил, как называется скорость изменения между ключами, и попросил выбирать не только линейную. Это интерполяция, ease-in / ease-out — её виды (easing). Сначала сделал как в Blender: кривая у ключа, действует на отрезок до следующего ключа (`da7b8ffe`). Пользователь ждал одну кривую на всю дорожку. Обсудили три варианта: дропдаун на дорожке с данными у ключей, данные у дорожки, или оба (дорожка по умолчанию, ключ переопределяет). Выбрал данные у дорожки — проще всего. Разные кривые на одной дорожке потом потребуют смены формата, до 1.0 это без миграции.

У `AnimationTrack` теперь необязательное `interpolation`: `linear` (по умолчанию, поле не пишется), `constant` (держит до следующего ключа, потом скачок), `ease-in`, `ease-out`, `ease-in-out` (кубические, за ключи не выходят). `valueAtFrame(keys, frame, interpolation)` — значит, сразу и превью, и экспорт, и delay. В web дропдаун в строке дорожки рядом с `+ key`, функция `setTrackInterpolation`.

Проверено: тесты contract (каждая кривая на кадрах 0 / 2.5 / 5 / 7.5 / 10, кривая на всех отрезках, схема, `graphAtFrame` с ease-in), web (`setTrackInterpolation`, `keyValueAt`). Headless на `?toast=animation`, дорожка `x` (−50 → 50 за кадры 0–23): на кадре 12 linear даёт 2.17, ease in — −35.80; constant — −50 на кадре 22 и 50 на 23.

## Луп шлейфа: циклический таймлайн

Пользователь прислал свой тост (`~/Downloads/xtc-toaster_20261119-181139.json`) и спросил, как поймать луп. Расчёт по кадрам показал, что луп не ловится: угол 0 → −30 и opacity 1 → 0 идут в одну сторону, кадр 95 отличается от кадра 0 в 27 параметрах из 36. А delay до начала дорожки держит её первый ключ, хвост прошлого цикла он не видит. Задержки в корне тут ни при чём: два экземпляра с delay 4 и 8 скрыты в layers. Я предложил вернуть дорожки к старту (ключи на 64): проверил на копии — движение кончается на кадре 82, кадр 95 совпадает с 0. Но пользователю нужен шлейф, который всё время идёт в одну сторону: новый слой рождается каждую часть цикла, назад ничего не возвращается.

Для этого сделан циклический таймлайн — `cycle` на ноде animation. Дорожка, которую через delay читают раньше первого кадра окна или позже последнего (окно — ниже), берётся по кругу, со сдвигом на длину окна. Всё делается в `animatedValues`. Value, анимированный дорожкой и стоящий за delay, тоже читается по кругу: `driverValues` берёт его через `animatedValues`. Рецепт шлейфа: одна дорожка на всю жизнь копии за цикл, n копий через delay с шагом `frames / n`. Тогда на каждом кадре n копий стоят в n равномерно разнесённых фазах, а на стыке цикла та, что закончила жизнь, рождается заново.

Тестовый тост `trail` — тост пользователя, переделанный под это. Шесть экземпляров `group 1` внутри `group 2`, у каждого угол и opacity идут через один delay 0 / 2 / … / 10 кадров. Таймлайн 12 кадров, `cycle` включён, дорожки только в одну сторону. Проверено: тесты contract (кадр до 0 и после конца читается по кругу, value за delay тоже), web, `test-toasts`. По `graphAtFrame` на каждом кадре шесть разных фаз. Headless: gif на 12 кадров отрендерился, contact sheet — кадры 6–11 повторяют 0–5. Видимый период там 6, а не 2: selectColor экземпляров выбирает разные оттенки (0 / 120 / 240), и на маках видны только две копии с hue 0. Рождение копии выглядит как скачок: opacity сразу 1. Пользователю предложено короткое появление на дорожке opacity (0 → 1 за первые 2 кадра).

## Окно таймлайна

Сначала по просьбе пользователя («экспорт с 8 до 12 кадра») в дропдауне экспорта появилось текстовое поле `frames` (`8-12`, `export.range`). Потом пользователь заметил, что `frames 23-47` никак не влияет на `cycle`. Так и было: `cycle` замыкал весь таймлайн 0…frames−1, а диапазон только вырезал кадры для файла. Под `cycle` это давало шов, если длина диапазона не кратна периоду. Решили сделать как в Blender: start / end у самого таймлайна. У ноды animation появилось необязательное `start`, а `frames` стало длиной окна (`timelineWindow` в contract). Внутри окна работают плейхед, play (с последнего кадра обратно на первый), рендер, экспорт и замыкание `cycle`. Ключи могут лежать вне окна — это разгон, который читает delay. В UI вместо поля `frames` два поля, `start` и `end`, оба конца включены: при смене start конец остаётся на месте, и наоборот. Таймлайн до start и после end затемнён. Поле `frames` из дропдауна экспорта и `export.range` убраны — две настройки одного и того же; до 1.0 это без миграции, zod выкидывает старое поле из сохранённого состояния.

`RENDER_MAX_FRAMES` считает кадры окна. Сервер рендерит `start … start+frames−1`, последовательность на диске нумерует с 0.

Проверено: тесты contract (`timelineWindow`, `cycle` замыкает окно, а не отсчитывает с 0), server (рендерятся кадры окна, нумерация с 0; через ws в gif ровно 2 кадра окна), web (`clampPlayhead` / `nextFrame` / прыжки по ключам внутри окна, `timelineEnd`). Headless на `?toast=animation`: start 6, end 17 — затемнение по краям, кнопки start / end, введённый кадр 30 откатывается, gif на 12 кадров.

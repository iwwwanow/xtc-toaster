# 2026-11-09 — расширение спринта 5 перед релизом: таймлайн blender, экспорт mp4, группы, ширины нод

Сначала планирование, потом в тот же день первые части кода: mp4, настройки экспорта, handle. Ветка `feat/animation-server`. Must спринта 5 закрыт: degas анимирован, пользователь прогнал его на локальном стеке, всё работает (`docs/diary/2026-11-08_degas-animated-elk-arrange.md`). До релиза пользователь попросил добавить ещё четыре фичи. Спецификация — `docs/sprints/sprint-5.spec.md`, раздел «extension 09.11».

## Что решено

- **Таймлайн как в blender.** Берём перетаскивание playhead и транспорт целиком: `start` / `‹ key` / `‹` / `play` / `›` / `key ›` / `end` и поле кадра. Ключи можно перетаскивать, провод параметра, брошенный на `+ track`, создаёт связанный трек. Горячие клавиши работают только при выбранной ноде animation. Зум: по умолчанию fit, Ctrl+колесо, кнопка `fit`. Раскладка повторяет blender, но вместо иконок кнопки с текстом. Таблица соответствия blender → наше — в спеке.
- **Группы треков** по ноде-источнику. Каждая группа — fieldset с видом рамки ноды. У группы есть строка-сводка с ключами всех её треков, и перетаскивание ключа в сводке сдвигает все ключи группы на этом кадре. Группу можно свернуть. Контракт не меняется: группы выводятся из связей.
- **Выпадающий блок экспорта** под `render animation`: формат `gif` / `mp4` и `loop`. `loop` уходит из ноды в тост, в новое поле `ToastGraph.export` (выбор пользователя: в файле тоста, а не в ноде и не только в браузере). В режиме `seconds` есть чекбокс `whole cycles`, по умолчанию включён. Включён — длина округляется до целых циклов. Выключен — длина ровно `seconds`, последний цикл обрезается на кадре.
- **Ширины по сетке uiu.** Нода занимает одну колонку owo — 190px. Подпись числового поля переезжает внутрь поля, как в нодах blender. Нода animation — 6 колонок, 1236px: 396 на каналы, 808 на таймлайн. `layers`, `input` и `output` — по 2 колонки. Последнее я выставил по умолчанию, пользователь не спрашивался.

Чем это перекрывает прежнюю спеку: mp4 больше не stretch, группы (stretch 2) и перетаскивание ключей (stretch 6) вошли в работу. Правило 03.11 «на ноду ничего не бросается» теперь не действует для `+ track`.

## Подводные камни на реализацию

- Сейчас xyflow по Delete удаляет выбранную ноду. Пока выбран ключ, Delete должен удалять ключ, поэтому Delete у xyflow на это время выключается.
- В свёрнутой группе handle треков переезжают на строку легенды, иначе провода повиснут в пустоте.
- В старых файлах `loop` лежит в ноде, а zod молча отбросит этот ключ. Миграции не будет (до 1.0 это нормально). У degas `{ seconds: 15 }` переносится в `export` вручную.
- Для yuv420p в mp4 нужен чётный размер — сделан pad белым. `libx264` в ffmpeg 7.1 из trixie есть, CI-образ это подтвердил.
- Подпись внутри поля шириной 174px длинные метки не вмещает (`x (% of width)` → `x %`), длинная форма уходит в `title`.

## Сделано в тот же день (после планирования)

- **Контракт.** Новое поле `ToastGraph.export?: { format?: "gif" | "mp4"; loop?: AnimationLoop }`. `loop` убран из `AnimationNode.data`. У `{ seconds }` появилось `wholeCycles?: boolean`, по умолчанию `true`. Старый `loop` в ноде zod молча отбрасывает — тест на это есть.
- **lib** (`assemble-gif.ts`).
  - `assembleGifFromFrames(dir, fps, out, { plays, frames })`. `frames` повторяет последовательность png через `-stream_loop -1` и обрезает её `-frames:v`. Палитра считается по одному проходу: на зацикленном входе palettegen не закончился бы никогда.
  - `assembleMp4FromFrames`: кадры кладутся на белый, нечётный размер дополняется до чётного белым, дальше `libx264 -preset veryfast`, yuv420p, `+faststart`.
- **Сервер.** `animationLength(data, export)` → `{ frames?, plays? }` (бывший `gifPlays`). Файлы называются `<uuid>.gif|mp4`, `findAnimation` возвращает файл с content-type.
- **web.**
  - Настройки `exportSettings` хранятся в session и проходят через `toGraph` / `toToastFile` / `fromToastFile` / `toSaved` / `fromSaved`. `withoutAnimation` их выбрасывает, так что смена настройки не запускает рендер.
  - Кнопка `render gif|mp4` с `▾`, под ней блок настроек (`.export-group` — `TODO(uiu)`, отмечено в `docs/backlog/2026-10-30_uiu-gaps-from-web.md`). Пустое значение для loop называется `forever` у gif и `once` у mp4.
- **Handle** (пользователь попросил по скриншоту). Пиксельный вход теперь на линии легенды слева сверху (`--legend-line: 0.5lh`), выход остался справа снизу. Пробовали сделать обе точки 6px вместо 4px — пользователь посмотрел: выглядит плохо, вернули 4px. Выход параметра на 3px ближе к полю (`--param-handle-offset`).

Проверено:

- `bun run typecheck` и `bun run test` зелёные.
- `docker build --target test .` зелёный: mp4-тесты lib прошли на ffmpeg 7.1 из trixie, libx264 там есть.
- Headless Chrome на dev-стеке, `?toast=animation`. Открыли `▾`, выбрали mp4: loop показывает `once`, настройки легли в localStorage. `render mp4` скачал `toast-2_signac_<ts>.mp4`: h264, yuv420p, 250×360, 72 кадра (24 × reps 3), 12 fps. Центр входа совпал с линией легенды (±1px), это проверено ещё на 6px.
- Пользователь руками это ещё не смотрел.

- **Ширины нод.** Колонка — `--grid-column: 190px`. Нода целиком (`.svelte-flow__node > .frame`) занимает одну колонку, `layers`, `input` и `output` — `.frame_span-2` (396px), animation — `.frame_span-6` (1236px), из них каналы 2 колонки. Подпись числового поля теперь внутри (`Slider.svelte`, `.param-field`): короткая метка (`x %`, `focal mm`, `deviation`), длинная форма в `title` (prop `hint`). Матрица 3 × `1fr`, картинка в output на всю ширину. Проверено скриншотами degas в headless Chrome: corners с `bottom-right y %` помещается в 190px, при fit-зуме ширины относятся как 190 / 396 / 1236. Пользователь ещё не смотрел. Пробелы uiu (токен колонки, поле с подписью внутри) — в `docs/backlog/2026-10-30_uiu-gaps-from-web.md`.

- **Шапка таймлайна** (`AnimationNode.svelte`). Порядок как в blender: в центре транспорт `start` / `‹ key` / `‹` / `play` / `›` / `key ›` / `end`, справа `frame` / `fps` / `frames` / `fit`. `+ track` остался в верхней строке колонки каналов, на одном уровне с линейкой. Любой ход останавливает play и не выходит за отрендеренные кадры. `‹ key` / `key ›` ходят только по ключам, которые попадают в рендер. Линейку можно тащить (pointer capture), каждый пройденный кадр рендерится по правилу latest-wins. Зум: по умолчанию fit (`timelineWidth / end`, не меньше 4px), Ctrl+колесо — ×1.25 вокруг кадра под курсором, `fit` возвращает. Обработчик колеса не passive, иначе браузер зумит страницу. Подписи линейки идут шагом 1 / 2 / 5 / 10…, не ближе 32px. Проверено в headless Chrome на degas: `key ›` → 23, `‹ key` → 0, перетаскивание с 25% на 75% → кадры 6 → 17, два шага колеса → ширина 796 → 1244px, кадр под курсором на месте, `fit` → 796. Пользователь ещё не смотрел.
- **Фон прозрачности в output** (просил пользователь): шахматка `.transparency` в стиле Photoshop, клетка 8px, `--LIGHT` / `--WHITE`. Проверено на `?toast=animation`: прозрачная половина после move −50% видна.

Подводные камни сессии: если вызвать `rulerLabels(end)` по-старому, без px, `rulerStep` получает `undefined` и уходит в бесконечный цикл — вкладка виснет, а CDP `Runtime.enable` не отвечает. Теперь на px ≤ 0 он бросает ошибку. Зависшая вкладка сохраняется в профиле Chrome, поэтому каждый запуск — с новым `--user-data-dir`. Эмуляция размера окна в CDP (`Emulation.setDeviceMetricsOverride`) живёт только в своей сессии — скриншоты фрагментов снимать в том же подключении, иначе кадр пустой. `pkill -f "remote-debugging-port=9333"` в той же bash-команде убивает и сам shell (паттерн есть в его командной строке). Headless Chrome гасить по PID.

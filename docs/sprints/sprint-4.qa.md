# QA — спринт 4: composer (ветка `feat/composer`)

Ручная проверка перед мержем. Только хрупкие места: автотесты зелёные, здесь то, что видно лишь глазами или живёт на стыке web ↔ server.

Стек: `docker compose up -d`, poppies загружается сам, `RENDER_MAX_LAYERS` в dev — 4. Графы открываются ссылками (`?toast=<name>`, файлы в `tests/toasts/`, что каждый ожидает — `tests/toasts/README.md`). Рендер / ошибка у всех тостов уже сверены скриптом 29.10 — руками остаётся то, что видно глазами, и интерактив.

## 1. Разветвление и копии (server)

- [x] [fork-3](http://localhost:5173/?toast=fork-3) — все 3 слоя видны: маки сверху, зелёный `add` полупрозрачный, под ним hue noise
- [x] [fork-fill](http://localhost:5173/?toast=fork-fill) — **маки чистые красные** поверх полупрозрачного синего на сером. Маки пропали или посинели → буфер протёк между ветками

## 2. Строки composer — на [fork-3](http://localhost:5173/?toast=fork-3)

- [x] перетащить строку `⠿` на другое место → **провод едет вместе со строкой**, картинка меняется
- [x] после перестановки у новой нижней строки select заблокирован, у бывшей нижней разблокирован и сохранил режим
- [x] `+ layer` → строка сверху, провода остальных не съехали
- [ ] `×` на средней строке → строка и её провод исчезают, остальные на месте; затем `+` — новая строка без чужого провода
- [ ] смена blend mode (`add`, `lch-hue`) → перерисовка
- [ ] во время рендера кнопки / select / `⠿` заблокированы

## 3. Связи — на [fork-3](http://localhost:5173/?toast=fork-3)

- [ ] провод на занятый вход (нода или строка) → заменяет старый
- [ ] конец существующего провода — на другую строку / ноду → переехал; в пустоту → удалён
- [ ] цикл и провод в input не рисуются — handle не подсвечивается
